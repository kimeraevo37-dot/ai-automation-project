# 用語集

この用語集は、本文を読んでいて言葉の意味で止まったときに使います。操作の順番は本文を確認してください。

| 用語 | 一文での説明 |
| --- | --- |
| Repository | プロジェクトのファイルと、それまでの変更の記録をまとめて置く場所です。 |
| Current repository | GitHub Desktopで、いま操作する対象として開いているプロジェクトです。 |
| Branch | 変更の流れを分けて管理するための名前です。 |
| main | この教材で通常使う、基本の変更の流れの名前です。 |
| Changes | まだ保存記録にしていない変更の一覧です。 |
| Diff | ファイルのどこが変わったかを比べて見る表示です。 |
| Summary | 今回何を保存するかを短く書く入力欄です。 |
| Commit | 確認した変更を、パソコン側の履歴として保存する操作です。 |
| Push | パソコン側に保存した変更を、GitHubへ送る操作です。 |
| History | これまでに保存した変更を順番に見る画面または記録です。 |
| README.md | プロジェクトの目的、再開方法、安全ルールを書く案内ファイルです。 |
| AGENTS.md | Codexが作業を始める前に読む、プロジェクト固有のルールです。 |
| ROADMAP.md | プロジェクトの目的、優先順位、現在のフェーズを確認する文書です。 |
| COMPANY_RULE.md | 人間とCodexの役割、承認が必要な操作、停止条件を決める文書です。 |
| Private repository | 内容を公開せず、許可された人だけが見られるようにしたリポジトリです。 |

## CommitとPushの違い

Commitはパソコン側へ変更を保存する操作、Pushはその保存内容をGitHubへ送る操作です。Commitしただけでは、ブラウザ版GitHubには反映されません。

## 後回しの用語

`Fetch origin`、Raw画像、Public画像、高度なBranch運用、Revert、Reset、Force pushは、初稿では扱いません。必要になった場合だけ、更新版またはトラブル集で確認します。
