# 第三者テスト実施ガイド

## 1. テスター向け説明

これは技術力やGitの知識を試すテストではありません。Chapter 00〜11を初めて読む人が、安全に進められるかを確認するためのテストです。

分からない、迷った、止まりたくなった場面は大切な記録です。無理に解決しようとせず、その時点の画面と迷った内容を観察者へ伝えてください。

## 2. テストの目的

テスターが教材を読みながら、次の正常フローを安全に再現できるかを確認します。

1. 正しいテスト用Privateリポジトリを確認する
2. 基盤3文書を作成し、第1Commit・Pushを行う
3. CodexへREADME.mdだけを依頼する
4. README.mdだけを第2Commit・Pushする
5. GitHub上の反映、Commit履歴、次回の再開方法を確認する

本番の `AI Automation Project` はテスト対象にしません。第三者テストは、このガイドを作成した時点では未実施です。

## 3. 所要時間

- 通し実施：60〜90分を目安にします。
- 分割実施：3回に分け、各回20〜30分を目安にします。

時間は評価対象ではありません。疲れた場合や安全上の停止条件に当てはまった場合は、途中で止めて構いません。

## 4. 必要なもの

- GitHubアカウントを使用できる環境
- GitHub Desktop
- Codex
- 新しいテスト用Privateリポジトリ
- 教材のChapter 00〜11
- 観察者が記録するためのメモ

テスターの氏名、メールアドレス、アカウント名、URL、ローカルパス、画面画像は記録しません。

## 5. 開始前チェック

テスターと観察者は、開始前に次を確認します。

- [ ] GitHub DesktopとCodexを起動できる
- [ ] 新しいテスト用Privateリポジトリを使用する
- [ ] 本番リポジトリや日常作業用リポジトリではない
- [ ] テスト中に個人情報・認証情報を教材やファイルへ書かない
- [ ] CommitとPushはテスター本人が行う
- [ ] 分からない場合は止めてよいと理解している

どれか一つでも確認できない場合は、テストを開始しません。

## 6. テスト中のルール

- テスターはChapterを順番に読み、自分で判断して進めます。
- 観察者は、迷った時点、操作を止めた時点、質問を記録します。
- 観察者は答えや操作手順を先回りして教えません。
- Commit・Pushの直前には、テスター自身がChangesとSummaryを確認します。
- テスト中に新しい教材内容、テンプレート、画像を作成・変更しません。

## 7. 止まるべき条件

次のいずれかに当てはまる場合は、そのまま操作を続けません。

- 対象リポジトリが分からない、または本番リポジトリの可能性がある
- Changesに教材想定外のファイルがある
- README.mdだけのはずなのに他のファイルがChangesにある
- 個人情報や認証情報が表示・保存されそう
- Commit対象、Summary、Push対象に自信がない
- 教材と現在の画面状態が大きく異なる
- Codexが意図しないファイルを変更した
- 履歴を書き換える必要があるように見える

停止したら、Commit・Push・履歴操作を行いません。観察者は「どのChapterで、何が表示され、何に迷ったか」だけを記録します。

## 8. 通し実施の流れ

1. 開始前チェックを行います。
2. Chapter 00〜03を読み、対象リポジトリと `main` を確認します。
3. Chapter 04〜08を読み、基盤3文書を作成し、第1Commit・Pushまで進めます。
4. Chapter 09〜10を読み、README.mdだけを作成し、第2Commit・PushとGitHub上の確認まで進めます。
5. Chapter 11を読み、次回の再開方法を確認します。
6. テスト終了後の確認と感想記録を行います。

## 9. 分割実施の流れ

### 第1回：環境と基盤文書

Chapter 00〜07を対象にします。対象リポジトリ、`main`、最小フォルダ構成、基盤3文書を確認します。第1Commit前で止めても構いません。

### 第2回：第1CommitからREADME作成まで

Chapter 08〜09を対象にします。基盤3文書だけを第1Commit・Pushし、GitHub上で確認してから、CodexへREADME.mdだけを依頼します。

### 第3回：README保存と再開

Chapter 10〜11を対象にします。README.mdだけを第2Commit・Pushし、GitHub、Commit履歴、次回の再開方法を確認します。

各回の終了時に、現在のChapter、Gitの状態、次に読むChapterだけを記録します。次回開始時は、対象リポジトリとGitの状態を確認してから再開します。

## 10. 観察者の声かけルール

観察者は、テスターの操作を代わりに行いません。次のような中立な声かけにとどめます。

- 「教材の該当箇所をもう一度確認してみてください。」
- 「今、何を確認しようとしていますか？」
- 「次に何をすればよいと書かれていますか？」
- 「安全上、ここで止める条件に当てはまりますか？」

次は行いません。

- 正しいボタンや答えを直接教える
- Commitメッセージや操作を代わりに入力する
- 迷った記録を残さず、先へ進むよう促す
- 停止条件に当てはまる状態で、テスト完走を優先する

## 11. 記録する最低限の項目

各Chapterまたは停止時点について、次だけを記録します。

- Chapter番号
- 自力で完了できたか
- 迷った、または止まった操作
- 分からなかった用語または画面表示
- 観察者が介入したか
- 次に何をすればよいか分かったか

CommitやPushを行うChapterでは、追加で次を記録します。

- Changesを確認できたか
- Summaryを確認できたか
- CommitとPushを区別できたか

記録は事実を短く残します。「不安そうだった」などの推測や、テスターを特定できる情報は記録しません。

## 12. テスト終了後の確認

観察者は、次を確認します。

- 総合結果：PASS／CONDITIONAL PASS／FAIL
- 完了または停止までの所要時間
- 止まったChapterと、実際に起きた操作・質問
- 自力で復帰できたか
- 教材本文、画像、Codex指示、UI差異、テスター固有環境、操作ミスのどれに分類できるか
- 教材修正が必要な箇所と、FAQ候補として残す箇所
- 次回再テストで確認する項目

PASSは軽微な読み直しだけで安全に完了した場合、CONDITIONAL PASSは教材を読み直して安全に復帰できた場合、FAILは教材だけでは安全に復帰できない場合です。

## 13. 個人情報保護

- 氏名、メールアドレス、GitHubユーザー名、ローカルパス、URL、通知、認証情報を記録しません。
- 画面を共有する必要がある場合も、個人情報や認証情報が見える状態では共有しません。
- 個人情報や認証情報が表示されそうな場合は、テストを止めます。
- 問題記録には、リポジトリ名ではなく「テスト用Privateリポジトリ」と記載します。

## 14. テスターへお願いする感想

テストの最後に、答えや評価を求めず、次を短く聞きます。

- 最も迷ったChapterはどこでしたか？
- 読み直して進めた箇所はありましたか？
- 画像、用語集、チェックリスト、FAQ、トラブル集で役立ったものはありましたか？
- 次に同じ作業をするとき、どこを見直したいですか？

感想は教材改善の参考として扱い、個人を評価するためには使いません。
