# Chapter 3：正しいリポジトリを確認する

## この章の目的

GitHub DesktopとCodexが、同じ正しいリポジトリを見ていることを人間が確認します。

## なぜ確認が必要か

テストでは、GitHub Desktopで操作したリポジトリと、Codexが確認したローカルの状態が最初は一致しませんでした。そのため、Codexは第1Commitを確認できず、README.mdの作成を止めました。

これは失敗を急いで直す場面ではありません。リポジトリ名と場所を確認してから再開すればよい問題です。

## 確認する3項目

作業を始める前に、次の3項目を確認します。

1. **Current repositoryの名前** — GitHub Desktopで現在開いているリポジトリ名です。
2. **Current branch** — この教材では通常 `main` を使います。
3. **ローカルパス** — パソコン上で、そのリポジトリが置かれている場所です。

ローカルパスにはWindowsのユーザー名が含まれる場合があります。教材画像では、必要がない限りパス全体を表示しません。

## GitHub Desktopで確認する

1. GitHub Desktopを開きます。
2. 画面左上の **Current repository** を見ます。
3. これから作業するリポジトリ名と一致するか確認します。

Current repository が対象リポジトリになっていることを確認します。名前が長い場合は末尾が「...」で省略されることがあります。

4. 画面上部の **Current branch** が `main` か確認します。
5. 不安な場合は、Repositoryメニューからエクスプローラーで場所を開きます。
6. 開いたフォルダの名前と、Codexで開いているフォルダを確認します。

> **画像候補：S-001**
> GitHub Desktopで、現在選択されているリポジトリ名を確認する画面。
> 読者が確認する箇所：画面左上のCurrent repositoryと、画面上部のCurrent branch。
> 暫定判定：必須。

## Codex側で確認する

Codexへ、次のように依頼します。

```text
作業を始める前に、現在のリポジトリ名、現在のローカルパス、Gitの状態、そして本番リポジトリかテスト用リポジトリかを確認して報告してください。ファイルは変更しないでください。
```

Codexの報告とGitHub Desktopの表示が一致することを確認します。GitHubのブラウザ版は、Push後の反映確認に使います。

## 一致しない場合

次の順で対応します。

1. 作業を止めます。
2. GitHub DesktopのCurrent repositoryを選び直します。
3. GitHub Desktopで開いたフォルダのローカルパスを確認します。
4. 正しいリポジトリをCodexで開き直します。
5. 人間とCodexで、リポジトリ名・ローカルパス・Gitの状態をもう一度確認します。

この章では、履歴の書き換えや高度なGit操作は行いません。

## 画像再判定

ローカルパスは重要な確認項目ですが、個人情報を含む可能性があります。S-001に安全なパスが写らない場合は、本文の手順だけで確認します。別の画像を追加する必要は、撮影用の安全なパスを用意できるか確認してから判断します。
