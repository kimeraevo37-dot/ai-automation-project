# 教材掲載用 一次体験の選定

## 目的と選定方針

このファイルは、Version 0.1で確認した一次体験を、初心者向け教材へ掲載する優先度で分類するための選定記録です。教材本文、画面画像、FAQ本文は作成しません。

- **A：教材本文に必須** — 初回の正常な流れを進めるために必要な内容
- **B：トラブルシューティングに掲載** — 通常の流れから外れた場合の対処
- **C：FAQに掲載** — 短い質問と回答で解消できる内容
- **D：開発ログのみに保存** — 背景として価値はあるが、初回教材を複雑にする内容
- **E：追加検証が必要** — 詳細な原因や再現条件が未確認の内容

「確認済み事実」は、Version 0.1のファイル、Commit履歴、通しテスト、再テストに基づくものです。原因や個別操作が詳細未記録のものは、具体的な教材手順にせず追加検証へ分類します。

## 教材本文に必須とする内容

次の6点は、初回フローを成立させるため本文に含める。

1. 正しいリポジトリを選び、名前とローカルパスを確認する。
2. AGENTS.md、ROADMAP.md、COMPANY_RULE.mdを作成する。
3. 基盤3文書を先に差分確認・Commit・Pushする。
4. Changesが空になってからREADME.mdだけを作成する。
5. CommitとPushは人間が行い、Codexは実行しない。
6. Push後にブラウザ版GitHubで対象ファイルとCommit履歴を確認する。

## トラブルシューティングに掲載する内容

- Changesに基盤3文書とREADME.mdの4ファイルが表示された。
- 空フォルダがGitHubに表示されない。
- GitHub Desktopで別のローカルリポジトリを開いている。
- Codexの確認とGitHub Desktop・ブラウザ版GitHubの表示が一致しない。

Commit対象の間違い、Summaryの不一致、Push後の修正、Pushしたはずのファイルがない問題は、具体的な再現記録を得るまで追加検証とする。

## FAQに掲載する内容

- 空フォルダがGitHubに見えないのは失敗か。
- `.gitkeep`は必ず必要か。
- CommitとPushの違いは何か。
- CodexはCommitやPushを実行するのか。

## 必要な画面候補

画像は今回作成しない。将来の実画面収集では、個人情報・認証情報を伏せたうえで次を候補とする。

1. GitHub Desktopで正しいCurrent repositoryを選ぶ画面
2. 基盤3文書だけがChangesに表示される画面
3. SummaryとChangesの対象ファイルを見比べる画面
4. Push origin後のGitHubブラウザ版のファイル一覧
5. README.mdだけがChangesに表示される画面
6. 空フォルダがローカルにはあり、GitHubに表示されない比較画面
7. GitHubのCommit履歴で第1・第2コミットを確認する画面

## 初心者教材へ入れすぎない方がよい内容

- テンプレート制作時の保存先ずれの詳細
- 再テストの内部的な検証手順
- 原因が未確定のCommit・Summary・Push後修正の個別対処
- Revert、履歴書き換え、破壊的Git操作の詳細手順
- 購入者データのない価格や販売可能性の議論

これらは開発ログまたは追加検証の対象として保持し、初回教材の正常な流れを複雑にしない。

## 選定上の確認

- **確認済み事実:** 基盤3文書とREADME.mdの二段階Commit、空フォルダのGit追跡、再テストでREADME.mdだけがChangesへ表示された結果。
- **推測・仮説:** 正しいリポジトリ確認や二段階Commitが第三者の初心者にも理解しやすいこと。
- **未確認:** 詳細未記録のCommit対象・Summary・Push後修正の原因と、購入者に必要な画面数。
