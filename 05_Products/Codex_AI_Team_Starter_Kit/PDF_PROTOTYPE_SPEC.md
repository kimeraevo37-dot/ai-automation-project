# PDF教材 試作仕様

## 1. 目的

Windowsのメモ帳ではMarkdown本文を読めても、教材内の画像は表示されないことが確認された。PDFは、初心者が画像付きの手順を追加設定なしで読めるようにするための閲覧用派生物として試作する。

Markdownを正本とし、PDFだけを先に修正しない。第三者テストは未実施であり、この仕様は試作のための暫定仕様である。

## 2. PDFの役割

- `01_Course.pdf`：通常の学習を、画像付きで順番に読むための閲覧版
- `02_Appendix.pdf`：用語確認、Commit前確認、短い疑問、想定外の状態への戻り先
- Markdown版：更新元・テキスト確認・リンク確認に使う正本
- Templates：購入者がコピーして編集する作業用ファイル

## 3. 01_Course.pdf の構成

1. 表紙
2. PDF閲覧者向けの短い開始案内
3. 目次
4. Chapter 00〜11
5. 更新版を確認する案内

`START_HERE.md` の内容は、意味を変えずにPDF冒頭へ必要最小限だけ反映する。`.md` が開けない場合の説明や開発リポジトリ向けの説明は入れない。README.txtからPDFを開いた購入者が、次にChapter 00へ進める案内を優先する。

画像は本文中の対応手順の直後へ配置する。対象はS-001、S-003、S-004、S-005、S-006、S-007、S-009、S-010の8枚とする。

## 4. 02_Appendix.pdf の構成

1. 付録の使い分け
2. Commit前チェックリスト
3. 用語集
4. FAQ
5. トラブル集
6. 本文へ戻る案内

付録は通常の本文を繰り返す場所ではなく、迷ったときに必要な項目へ戻るための資料としてまとめる。

## 5. Templatesとの役割分担

TemplatesはPDFにせず、編集可能なMarkdownファイルのまま配布する。PDFは読んで理解するための形式、Templatesは購入者がコピーして自分のリポジトリで使うための形式として分ける。

## 6. Markdownを正本とする更新ルール

1. 先にMarkdown、画像、テンプレートを必要に応じて更新する。
2. 本文・付録・画像の整合を確認する。
3. `01_Course.pdf` と `02_Appendix.pdf` を再作成する。
4. PDFの章名、画像、ページ構成、可読性を確認する。
5. 更新履歴と版番号を確認する。

PDFだけの先行修正、またはMarkdownと異なる手順の追加は行わない。

## 7. START_HEREのPDF向け調整方針

- PDFを開いた購入者向けに、「次はChapter 00から進める」と案内する。
- GitHub Desktop、Codex、Privateリポジトリ、安全停止の基本方針は残す。
- `.md` の開き方、メモ帳、PDF版の予定など、PDF閲覧者に不要な説明は省く。
- Markdown版と異なる操作手順、サポート約束、追加機能は入れない。
- PDF専用の案内は短くし、開始導線だけに限る。

## 8. 画像配置・可読性ルール

- 画像は対応する操作説明の近くに1枚ずつ置く。
- UI内の文字、ファイル名、`main`、Changes、Summary、Push originが読めないほど縮小しない。
- 1ページに無理に複数の画面を詰め込まない。
- 画像がページをまたぐ場合は、画像全体を次ページへ送る。
- 画像の前後に短いキャプションを置き、画像だけに操作説明を依存しない。
- 公開用Public画像8枚だけを使い、Raw画像・旧S-010・S-010 v2は使わない。

## 9. PDF作成後の確認項目

- 2冊のPDFが指定どおりの構成である。
- 目次、章順、付録順、ページ番号が正しい。
- 8画像が対応する手順と一致し、文字が読める。
- 改行切れ、重なり、画像の欠落、文字化けがない。
- PDF内の開始案内がMarkdownの安全ルールと矛盾しない。
- Markdown更新後にPDFを再作成したことを確認できる。

PDF試作時は、生成後に各ページを画像として確認し、配置と可読性を目視確認する。

## 10. 第三者テストで確認する項目

- PDFを自力で開けるか。
- PDFの開始案内だけでChapter 00へ進めるか。
- 目次から必要なChapterや付録を探せるか。
- 画像内の操作対象と文字を読めるか。
- Markdown版とPDF版のどちらが読みやすいか。
- PDF版があっても、Commit・Pushの安全停止判断を理解できるか。

第三者テストの結果はまだ存在しない。質問や迷った箇所は、実施後にPDF構成の確定材料として扱う。

## 11. Version 1.0前に未確定の事項

- PDFを正式な同梱物にするか。
- PDFのページサイズ、表紙、版番号、更新履歴の見せ方。
- 本文と付録を2冊に分ける最終判断。
- PDFとMarkdownのどちらを主入口にするか。
- 第三者テストで確認された可読性・導線・画面差異への対応。
- 販売サービス上での配布形式。

## 12. PDF試作時の作業順序

1. 第三者テスト前の現行Markdown・Images・付録を正本として固定する。
2. `01_Course.pdf` 用の章順とPDF向け開始案内を準備する。
3. `02_Appendix.pdf` 用の付録順を準備する。
4. Public画像8枚を対応箇所へ配置してPDFを試作する。
5. 各ページを目視確認し、Markdownとの差異を確認する。
6. 第三者テスト後に、PDF同梱・構成・導線の最終判断を行う。

この仕様の作成時点では、PDFファイルは作成しない。
