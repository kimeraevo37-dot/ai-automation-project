## 1. このテンプレートの目的

Codexへ最初の安全なタスクを依頼するためのテンプレートです。最初から大きな開発を頼むと、変更内容が分かりにくくなります。

最初のタスクを `README.md` の作成にすると、コードを書かずに、作成・確認・Git差分確認・Commit・Pushという基本の流れを練習できます。READMEはプロジェクトの案内板なので、次回の再開にも役立ちます。

## 2. 実行前チェック

- [ ] ルート直下に `AGENTS.md` がある。
- [ ] `ROADMAP.md` がある。
- [ ] `COMPANY_RULE.md` がある。
- [ ] GitHub Desktopで正しいリポジトリを選んでいる。
- [ ] 未保存の重要ファイルがない。
- [ ] 個人情報や認証情報を入力しようとしていない。
- [ ] 今回は `README.md` だけを作ると決めている。

## 5. Codexの報告を確認する

Codexの報告を読んだら、次を確認します。

- `README.md` 以外が変更されていないか。
- プロジェクト名が正しいか。
- 存在しないフォルダが書かれていないか。
- 個人情報や認証情報が含まれていないか。
- 誇張や、事実でない説明がないか。
- CodexがCommitやPushを実行していないか。

分からない点や問題があれば、CommitせずにCodexへ修正を依頼します。

## 6. GitHub Desktopで差分を確認する

1. GitHub Desktopを開く。
2. 対象リポジトリを選ぶ。
3. **Changes** を確認する。
4. `README.md` だけが変更されているか確認する。
5. 緑色（追加）と赤色（削除）の差分を確認する。
6. 問題がある場合はCommitしない。
7. 問題がなければSummaryを入力する。

画面やボタン名はアプリの更新で変わる場合があります。実際の画面表示を確認して操作してください。

## 7. CommitとPush

- **Commit:** 変更内容を自分のパソコン側の履歴として記録すること。
- **Push:** Commitした履歴をGitHubへ送ること。

Codexは実行しません。内容を確認して問題がなければ、人間が次の順で操作します。

1. Summaryへ `docs: プロジェクトREADMEを追加` と入力する。
2. Commitを実行する。
3. Commit完了を確認する。
4. **Push origin** を実行する。
5. ブラウザ版GitHubで `README.md` を確認する。

## 8. 問題があった場合

- **README.md以外も変更されている:** Commitせず、変更内容を確認してCodexへ相談する。
- **既存README.mdが上書きされた:** すぐにPushせず、差分を確認して復元方法を相談する。
- **存在しないフォルダが記載された:** 実際の構成に合わせて修正する。
- **文字化けやMarkdown崩れがある:** 表示を確認し、修正してから差分を再確認する。
- **個人情報が含まれている:** Pushせず、情報を取り除いてから確認する。
- **GitHub Desktopに変更が表示されない:** 正しいリポジトリを選んでいるか、ファイルを保存したかを確認する。
- **Commitしたがブラウザ版GitHubへ反映されない:** Pushが完了しているかを確認する。

問題が解決するまではPushしません。すでにPushした場合も、慌てて履歴を書き換えず、状況を確認してから修正します。

## 10. 次に進む条件

次の高度なタスクへ進む前に、次を完了させます。

- README.mdを自分で読んで理解できる。
- Codexの変更内容を確認できた。
- CommitとPushの違いを理解した。
- GitHubブラウザ版で反映を確認した。
- 問題が発生したときにCommitやPushを止められる。

ここまでできれば、完璧でなくても最初の流れは成功です。次も一度に一つの小さなタスクだけを進めます。
