# 第三者テスト計画 — Version 0.3

## 1. 目的

Git・GitHub・Codexの経験が少ない第三者が、教材のChapter 0〜11を順に読みながら、安全に次の正常フローを再現できるか確認する。

1. 正しいテスト用リポジトリを確認する。
2. 基盤3文書を作成する。
3. 基盤3文書だけを第1Commit・Pushする。
4. Codexへ`README.md`一件だけを依頼する。
5. `README.md`だけを第2Commit・Pushする。
6. ブラウザ版GitHubとCommit履歴を確認する。
7. 次回の再開方法を理解する。

この計画は、教材の再現性を確認するためのものであり、テスターの能力や作業速度を評価するものではない。

## 2. テスター条件

- Git・GitHubは初心者である、または使用経験が浅い。
- Codexは初心者である、または使用経験が浅い。
- プログラミング経験は必須としない。
- Windows、GitHub Desktop、Codexを利用できる。
- 新しいPrivateテスト用リポジトリを使用する。
- 本番の`AI Automation Project`やテスター自身の重要なリポジトリを使用しない。

テスター名、メールアドレス、GitHubユーザー名、ローカルパス、認証情報は記録しない。記録上は`テスターA`のような匿名の識別子だけを使う。

## 6. 問題分類

| 分類 | 内容 | 記録例 |
| --- | --- | --- |
| A：教材本文の問題 | 説明不足、順序不明、用語不足、完了条件が確認できない。 | 「Chapter 8でCommit前の確認対象が分からなかった。」 |
| B：画像の問題 | 画像の位置が不明、画面が違う、確認したい場所が見えない。 | 「S-005にあるPush originの位置を画面上で見つけられなかった。」 |
| C：Codex指示の問題 | 依頼内容、作業範囲、報告の確認方法が分からない。 | 「README.mdだけを依頼する意図を理解できなかった。」 |
| D：GitHub Desktop / GitHub UI差異 | 教材と現在の画面、ボタン名、表示位置が大きく違う。 | 「教材の画面と違い、Current repositoryの場所を特定できなかった。」 |
| E：テスター固有環境 | OS、アカウント状態、既存設定など教材本文だけでは統制できない事情。 | 「組織アカウントの設定によりPrivateリポジトリを作成できなかった。」 |
| F：操作ミス | Summary誤入力、別リポジトリ選択、Commit対象の選択間違い。 | 「README.md以外の変更を含めようとしたが、Commit前に気づいた。」 |

問題は、推測で原因を決めない。画面上の状態、操作、教材の該当箇所、テスターの質問を分けて記録する。

## 7. 停止条件

次のいずれかに該当した場合、テスターと観察者は操作を止める。

- 対象リポジトリが分からない。
- 本番リポジトリを開いている可能性がある。
- Changesに教材想定外のファイルがある。
- `README.md`だけのはずなのに、他ファイルがChangesにある。
- 個人情報・認証情報が表示または保存されそうである。
- Commit対象またはPush対象に自信がない。
- 教材と画面状態が大きく違い、安全に判断できない。
- Codexが意図しないファイルを変更した。
- 履歴書き換えが必要に見える状況になった。

停止した場合は、そのまま操作を続けない。次だけを記録する。

- 停止したChapterと手順番号
- 画面上で確認できた状態
- 何に迷ったか、または何が一致しなかったか
- その時点で未Commitか、Commit後か、Push後か

個人情報・認証情報が表示された場合は、その値を記録・撮影・共有しない。

## 9. PASS / CONDITIONAL PASS / FAIL基準

| 判定 | 基準 |
| --- | --- |
| PASS | 軽微な読み直しだけで、安全に最後まで完了できた。停止条件に該当せず、成功条件を満たした。 |
| CONDITIONAL PASS | 途中で迷ったが、教材内の説明・画像・完了条件を読み直すことで安全に復帰できた。修正候補は記録する。 |
| FAIL | 教材だけでは安全に復帰できない、停止条件に該当した、または重大な誤操作につながる箇所があった。 |

観察者が答えを教えて進めた場合は、該当箇所を「自力完了」とは扱わない。

## 11. 再テスト条件

次の場合は、教材の修正後に同じ条件で再テストする。

- FAILになった。
- 誤ったリポジトリ、Commit対象、Push対象を選びそうになる問題があった。
- 本文、画像、Codex指示、UI差異が原因で停止した。
- 修正後に、同じ問題が解消したことを確認する必要がある。

再テストでは、変更した箇所だけでなく、Chapter 8からChapter 10までのCommit・Pushの連続性も確認する。

## 12. 個人情報保護

- テスターの氏名、連絡先、GitHubユーザー名、Windowsユーザー名、ローカルパス、URL、認証情報を記録しない。
- テストはPrivateリポジトリで行い、本番リポジトリを使用しない。
- 画面記録が必要な場合も、個人情報・認証情報が写る部分は記録しない。
- APIキー、アクセストークン、パスワード、`.env`の内容は教材・結果記録へ書かない。
- 問題を共有する場合は、個人を特定しない操作状況だけを記録する。
