# Troubleshooting

この記録は、実際の作業で確認された問題と、初心者が安全に確認するための対応を分けて残すものです。

## Trouble-T-001：ROADMAP_TEMPLATE.mdがTemplatesフォルダ外に作成された

### 症状

テンプレート群の中で、`ROADMAP_TEMPLATE.md`だけが`Templates`フォルダ外にあり、他のテンプレートと並ばなかった。

### 起きた状況

テンプレートの保存先を統一する前の作成作業で確認された。

### 確認された原因

保存先の指定と実際の配置が一致していなかった。

### 推測と未確認事項

最初の配置操作の詳細な経緯は未記録。

### 安全な対応

変更前に既存ファイルを確認し、テンプレート群の保存先を一つに統一してから差分を確認する。

### やってはいけないこと

元ファイルを確認せずに同名ファイルを複数作成する。

### 解決確認

現在の`ROADMAP_TEMPLATE.md`は`Templates`フォルダ内にある。

### 教材へ入れる注意事項

作成前に保存先を確認し、テンプレートは同じフォルダへまとめる。

### 関連ファイル

`05_Products/Codex_AI_Team_Starter_Kit/Templates/ROADMAP_TEMPLATE.md`

## Trouble-T-002：基盤3文書が未CommitのままREADME.mdを作成した

### 症状

GitHub DesktopのChangesに、`AGENTS.md`、`ROADMAP.md`、`COMPANY_RULE.md`、`README.md`の4ファイルが表示された。

### 起きた状況

基盤3文書を作成後、CommitせずにREADME.mdを作成した通しテスト。

### 確認された原因

基盤3文書が未Commitだったため、README.mdと同じ変更一覧に残っていた。

### 推測と未確認事項

GitHub Desktopの表示文言はアプリの更新で変わる可能性がある。

### 安全な対応

README.mdの前に基盤3文書を人間が確認し、第1コミット・Pushを完了する。Changesが空になってからREADME.mdを作成する。

### やってはいけないこと

4ファイルをREADME用のCommitとして誤認したままPushする。

### 解決確認

新しいテスト用リポジトリで、基盤3文書を第1コミット後にREADME.mdを作成し、ChangesにREADME.mdだけが表示されることを確認した。

### 教材へ入れる注意事項

基盤3文書が未Commitの場合はREADME.md以外もChangesに表示される。初回教材では二段階Commitを推奨する。

### 関連ファイル

`FIRST_TASK_PROMPT.md`、`FOLDER_STRUCTURE.md`

## Trouble-T-003：空フォルダがGitHubに表示されなかった

### 症状

ローカルには作成した空フォルダが、GitHubのブラウザ版には表示されなかった。

### 起きた状況

最小フォルダ構成を作成し、`.gitkeep`を追加しない通しテスト。

### 確認された原因

Gitは通常、空フォルダだけを追跡しない。

### 推測と未確認事項

利用者が空フォルダをGitHub上で必ず確認したいかは未確認。

### 安全な対応

作成失敗ではないと説明し、必要な場合だけ`.gitkeep`を追加して人間が差分を確認する。

### やってはいけないこと

空フォルダを表示させるためだけに、理由なく多数の`.gitkeep`を追加する。

### 解決確認

`FOLDER_STRUCTURE.md`へ説明を追加し、新しいテスト用リポジトリでも空フォルダがローカルにありGitで未追跡であることを確認した。

### 教材へ入れる注意事項

`.gitkeep`はGitの正式機能ではなく慣例であり、初期構成では必須ではない。

### 関連ファイル

`FOLDER_STRUCTURE.md`

## Trouble-T-004：GitHub Desktopで別のローカルリポジトリを開いていた

### 症状

人間は第1コミット完了を確認していたが、Codexが確認したローカル作業ツリーには基盤3文書が未追跡として残っていた。

### 起きた状況

再テスト用リポジトリで、第1コミット後の状態をCodexが確認した段階。

### 確認された原因

Codexが確認したローカルパスと、GitHub Desktopで操作したリポジトリの対応が最初は一致していなかった。

### 推測と未確認事項

GitHub Desktopで最初に選択されていた具体的なローカルパスは、記録から確定できない。

### 安全な対応

リポジトリ名、ローカルパス、GitHubのURLをそれぞれ確認し、対象が一致してから作業を再開する。

### やってはいけないこと

作業ツリーが空でないままREADME.md作成へ進む。

### 解決確認

ローカルのリモート参照とCommit履歴を確認後、作業ツリーが空であることを確認してREADME.md作成へ進んだ。

### 教材へ入れる注意事項

GitHub Desktop、ローカルGit、ブラウザ版GitHubは別々に確認し、名前だけでなくローカルパスも確認する。

### 関連ファイル

`FIRST_TASK_PROMPT.md`、再テスト用リポジトリのCommit履歴

## Trouble-T-008：CodexとGitHub Desktop・ブラウザ版GitHubの認識差

### 症状

人間のブラウザ版GitHubでの確認と、Codexが最初に見たローカルGit状態が一致しなかった。

### 起きた状況

再テスト用リポジトリの第1コミット後確認。

### 確認された原因

ローカルの参照状態を更新して確認した後、基盤3文書のCommitとPushが確認できた。

### 推測と未確認事項

表示の時間差だけだったか、リポジトリ選択の違いもあったかは確定していない。

### 安全な対応

GitHub Desktop、ローカルGit、ブラウザ版GitHubを分けて確認し、作業ツリーが空であることを確認してから次へ進む。

### やってはいけないこと

どれか一つの表示だけを根拠に、次のCommit・Pushを急ぐ。

### 解決確認

再テストでは基盤3文書とREADME.mdを別Commitに分け、最終的に作業ツリーが空であることを確認した。

### 教材へ入れる注意事項

表示が食い違うときは、リポジトリ名・ローカルパス・ブランチ・Changesを確認し、解決まで次のCommitやPushを行わない。

### 関連ファイル

`FIRST_TASK_PROMPT.md`、再テスト用リポジトリのCommit履歴

## 重要な安全方針

- Push後に慌てて履歴を書き換えない。
- ファイル内容に問題がなければ、そのまま次のCommitで修正できる場合がある。
- 認証情報や個人情報が含まれる場合は対応が異なるため、Pushを止めて安全な対応を優先する。
- Revertと履歴削除を安易に初心者へ勧めない。
- 正しいリポジトリ名とローカルパスを確認する。
- GitHub Desktop、ローカルGit、ブラウザ版GitHubを分けて確認する。
- 問題が解決するまで次のCommitやPushを急がない。
