# AI Automation Project — COMPANY RULE

## 1. Authority

### CEOにのみ許可されること

- 事業方針、商品公開、価格、販売開始の最終決定
- 外部サービス登録、有料契約、実際のSNS投稿、メール・DM送信
- 個人情報、APIキー、認証情報の入力・設定
- リポジトリ公開設定の変更と大規模な削除・構造変更

### Codexに許可されること

- ファイル調査、新規ファイルの下書き、既存ファイルの改善案作成
- コード・テンプレート・手順書・チェックリストの作成と修正
- テスト、整合性確認、Git差分とコミット候補の報告

Codexは、公開、販売、送信、課金、外部サービス登録、Push、認証情報利用、破壊的操作をCEOの明示的な承認なしに実行しない。

## 2. Workload and Continuity

- 作業量を増やすより、再利用可能な仕組みを作る。
- 最初の商品を完成させるまで、複数の商品を同時に作らない。
- 人間に大量の判断を求めず、推奨案は原則一つに絞る。
- タスクは中断可能な小さな単位に分け、体調不良日でもプロジェクトが壊れない設計にする。
- 作業量を増やす提案には、削減できる既存作業も併記する。

## 3. Single-Product Rule

最初の商品「初心者向け Codex AIチーム構築スターターキット」が完成するまで、新商品の本格開発、大規模SaaS、アフィリエイトサイト、YouTube主軸運用を始めない。新しい案は `01_CEO/Ideas.md` または適切なBacklogへ保管する。

## 4. Quality Rules

- 不明な事実を断定せず、推測・仮説・未確認を明記する。
- 収益を保証せず、実績のない数字を実績として扱わない。
- 参考情報と引用元を記録する。
- AI生成物は公開前にCEOが確認する。
- 初心者が再現できる具体的な手順と用語説明を書く。
- 著作権、商標、利用規約を尊重し、不必要に煽る表現を避ける。

## 5. Technical Rules

- 最小構成から始め、不要な依存関係を増やさない。
- 変更前に関連ファイルを確認し、小さく変更して小さく検証する。
- 実行方法とエラー時に確認するログをREADME等へ残す。
- 秘密情報をコードへ直接書かず、`.env` をGitへコミットしない。
- 削除・破壊的変更の前にはCEOの承認を得る。
- テストできない場合は、その理由を報告する。

## 6. Git Rules

- 1コミットにつき目的は一つにする。
- コミット前に差分を確認し、意味の分かるメッセージを書く。
- 無関係な変更、APIキー、パスワード、個人情報を混在させない。
- 破壊的なGit操作を独断で実行しない。
- Push前に変更内容をCEOへ要約し、承認を得る。
- ブランチ運用は、複雑さが必要になるまで最小限にする。

## 7. Privacy, Security, and External Communication

- 本名、住所、電話番号、金融・医療情報、認証情報を公開用ファイルに記載しない。
- 出所不明のコードを無確認で実行しない。
- CodexはSNS、note、メール、DMの下書きまでを担当し、実際の投稿・送信・公開はCEOが行う。
- 自動投稿を導入する場合も、初期段階はCEO承認制とする。
- なりすまし、スパム、大量投稿、実績誇張、対立を煽る表現をしない。

## 8. Decision Rule

迷った場合は次の順で判断する。

1. 安全性
2. 個人情報・認証情報の保護
3. CEOの明示的な指示
4. ROADMAP.md
5. COMPANY_RULE.md
6. 最初の商品完成
7. 継続可能性
8. 作業効率
9. 新規性

## 9. Stop Conditions

次の場合は作業を止め、CEOへ報告する。

- ファイル喪失、個人情報・認証情報露出のおそれがある。
- 指示同士に重大な矛盾がある。
- 有料契約、外部公開、本番環境への影響、法令・制度・利用規約の判断が必要になる。
- 医療、税務、社会保障制度など専門家確認が必要な事項がある。
