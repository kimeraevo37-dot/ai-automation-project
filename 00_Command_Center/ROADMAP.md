# AI Automation Project — ROADMAP

## 1. Project Overview

- **プロジェクト名**: AI Automation Project
- **運営形態**: 人間1名（CEO）と複数のAIエージェントによる個人事業準備プロジェクト
- **準備期間**: 2026年8月から約6か月
- **中長期の収益目標**: 月20万〜30万円。これは保証ではなく、継続可能な事業を目指す目標値である。
- **初期方針**: 売上を急がず、再利用可能な事業基盤を作る。
- **最初の収益モデル**: AI自動化ノウハウを販売するコンテンツ事業

## 2. Mission

AIエージェントを活用し、一人でも継続可能な自動化ワークフローを構築する。その構築過程で得た実践的な知識を、初心者にも再現可能なコンテンツ商品として提供する。

将来的には、note、PDF、Prompt Pack、GitHub、テンプレート、必要最小限のSaaSへ発展させる。

## 3. Target Customer

最初の顧客像は、次の条件に当てはまる初心者に絞る。

- ChatGPTは使っているが、CodexやAIエージェントの実践的な使い方が分からない人
- 副業または個人事業の作業を効率化したい人
- プログラミング経験が少ない人
- 高額なコンサルティングではなく、手頃なテンプレートや教材を求める人

## 4. First Product

**仮の商品名**: 初心者向け Codex AIチーム構築スターターキット

**商品内容**:

- Codex導入手順
- GitHub初期設定
- 推奨フォルダ構成
- ROADMAP.md、COMPANY_RULE.md、AGENTS.md のテンプレート
- AIエージェントの役割分担例
- 実際に使える指示プロンプト
- 作業チェックリスト
- 初心者がつまずきやすい点と対処
- 更新履歴

最初の商品が完成するまでは、別の商品開発を原則として始めない。新しい案は `01_CEO/Ideas.md` に保管し、現在の商品へ転用できるものだけを優先する。

## 5. Six-Month Phases

### Phase 1: 基盤構築（2026年8月）

**目標**

- GitHub運用を確立する。
- ROADMAP.md、COMPANY_RULE.md、AGENTS.md を完成させる。
- 基本フォルダ構成と作業ログの仕組みを整える。

**完了条件**

- 新しいCodexセッションでも、プロジェクトの目的と規則を理解できる。
- CEOが毎回ゼロから説明する必要がない。
- 変更内容をGitで追跡できる。

### Phase 2: ワークフロー試作（2026年9月）

**目標**

- リサーチ、構成作成、執筆、校正、品質確認を標準化する。
- SNS投稿案作成フローと作業テンプレートを試作する。

**完了条件**

- 一つのテーマから調査、構成、下書き、校正まで再現できる。
- 各工程の入力・出力と、CEOが確認する箇所が明文化されている。

### Phase 3: 実践記録（2026年10月）

**目標**

- Codexを使った構築過程、失敗、修正、改善を記録する。
- スクリーンショット、実例、初心者が理解しづらい点を整理する。

**完了条件**

- 商品に使える一次体験と再現手順が蓄積されている。
- 一般論だけでなく、実際の作業例を示せる。

### Phase 4: 商品制作（2026年11月）

**目標**

- スターターキットの初稿とテンプレート類を完成させる。
- サンプルリポジトリと初心者向けの説明を整える。

**完了条件**

- 購入者が最初から最後まで実行できる。
- 必要なファイルに欠落がなく、個人情報・認証情報を含まない。
- 収益保証や根拠のない表現がない。

### Phase 5: 試験運用（2026年12月）

**目標**

- 自分自身で教材を最初から実行し、手順を修正する。
- 無料公開部分、note販売ページの下書き、X・Threads投稿案を作る。

**完了条件**

- テスト環境で手順を再現できる。
- 販売ページ下書き、公開前チェック項目、最低10本のSNS投稿案が用意されている。

### Phase 6: 公開準備（2027年1月）

**目標**

- 制度面と収益化開始時期を確認する。
- 商品最終版、価格仮説、販売ページ、告知素材、公開後の改善方法を整える。

**完了条件**

- CEOが公開を承認している。
- 販売に必要な制度上の確認が完了している。
- 商品、販売ページ、告知素材、問い合わせ対応方針が揃っている。

## 6. Priority Order

判断は次の順で優先する。

1. 体調と継続可能性
2. 最初の商品完成
3. 品質と再現性
4. 自動化と省力化
5. 集客
6. 売上拡大
7. 新商品開発

## 7. Scope

**対象に含めるもの**

- Codex運用、GitHub管理、AIエージェント設計
- コンテンツ・テンプレート制作
- note販売準備、X・Threads投稿案作成
- 簡単な自動化ツールの開発

**初期段階では対象外とするもの**

- 顧客ごとの受託開発、電話・訪問営業、大量の個別DM
- 複数事業の同時立ち上げ、高額な広告出稿、大規模SaaS開発
- 収益保証を含む表現

## 8. KPI

準備期間中は売上だけをKPIにしない。主な指標は次のとおり。

- 完成した標準手順数と再利用可能なテンプレート数
- 人間の確認工程数と、1コンテンツ作成に必要な人間の作業時間
- 商品原稿の完成率
- テストで発見した問題数と修正率
- 公開可能な実例数とSNS投稿ストック数

## 9. Weekly Operating Rule

- 重要タスクは週最大3件、必須タスクは原則1日1件とする。
- タスクは15分・30分・60分単位に分解する。
- 体調不良日は、記録または確認だけでも完了扱いにできる。
- 未完了タスクは失敗とみなさず、次回へ繰り越す。
- 新しいアイデアは即着手せず、Ideas Backlogへ保管する。
- 毎週、完了・未完了・停止・次週の4項目を確認する。

## 10. Definition of Done

最初の到達点は、次のすべてを満たす状態である。

- スターターキットが完成している。
- 第三者が手順を再現できる。
- GitHub上で変更履歴を確認できる。
- 販売ページとSNS投稿案が準備されている。
- CEOの承認後に公開できる。
